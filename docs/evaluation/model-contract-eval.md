# 模型合同评测报告

> **评测性质**：模型合同与接地检查（contract and grounding check），不是人工标注准确率评测。
> 样例为合成数据，不代表真实平台数据，不应从中推断真实世界的精度指标。

## 概述

本评测通过 8787 代理向阿里云百炼 Token Plan 端点发送 12 个具有区分度的合成样例，
验证模型输出是否满足三条硬约束：

1. **合同通过**——返回 JSON 形状符合 zod schema（themes + complianceRisks 数组，字段类型正确）
2. **零幻觉引用**——模型引用的 reviewIds 和 policyIds 全部存在于输入数据集中，无一编造
3. **主题接地**——每个主题引用的评论内容与主题标签存在关键词重叠（粗粒度检查）

## 评测结果

| 指标 | 结果 |
|---|---|
| 合同通过率 | **12/12 (100%)** |
| 零幻觉引用率 | **12/12 (100%)**——0 个编造的 reviewId 或 policyId |
| 主题接地率 | **37/37 (100%)**——所有主题引用的评论均包含相关关键词 |
| 预算使用 | **12/20 次调用**（无需重试） |
| 延迟范围 | 最小 3.8s · 中位 5.8s · P95 8.6s · 最大 8.6s |

## 样例设计

12 个样例覆盖四种难度梯度，每个样例包含多条评论（3–10 条）以提升信息密度：

| 编号 | 难度 | 描述 | 延迟 | 主题数 | 风险数 |
|---|---|---|---|---|---|
| C1-thermal-strong | clear | 3/6 条评论提及发热 | 6.0s | 4 | 1 |
| C2-port-reset | clear | 3/5 条评论提及端口中断 | 6.9s | 3 | 2 |
| C3-mixed-signals | moderate | 8 条评论混合发热+端口+噪声 | 6.7s | 3 | 2 |
| C4-all-positive | negative | 5 条正面评论，无明确痛点 | 5.1s | 3 | 1 |
| C5-price-complaints | clear | 3/5 条评论吐槽价格 | 4.6s | 2 | 1 |
| C6-weak-thermal | hard | 仅 1 条附带提及"微温" | 4.9s | 3 | 1 |
| C7-eu-market | moderate | 纯欧盟市场+欧盟政策 | 4.9s | 3 | 1 |
| C8-mixed-market | moderate | 美国+欧盟混合市场 | 7.1s | 4 | 2 |
| C9-no-policies | negative | 无政策数据，应返回 0 合规风险 | 3.8s | 3 | 0 |
| C10-adversarial-ids | hard | ID 形似交叉，防混淆 | 4.1s | 2 | 1 |
| C11-large-dataset | moderate | 10 条评论 × 4 产品 | 8.6s | 4 | 2 |
| C12-ambiguous | hard | 情感混杂评论 | 5.8s | 3 | 1 |

### 关键发现

- **C9 负样本正确处理**：当数据集不含政策时，模型返回 0 条合规风险，没有编造 policyId。
- **C10 对抗 ID 通过**：reviewId 含 "policy" 字样、policyId 含 "review" 字样时，模型没有混淆两类 ID。
- **C6 弱信号检测**：仅 1 条评论附带提及"微温"，模型仍识别出相关主题并正确引用。
- **延迟可预测**：所有调用在 4–9 秒内完成（enable_thinking:false 后的推理延迟），无需重试。

## 局限性诚实声明

1. **合成数据**：样例由开发者构造，不代表真实电商平台评论的复杂度和噪声水平。
2. **小样本**：12 例不足以做统计显著性结论；应理解为「合同合规与接地检查」，不是准确率评测。
3. **接地检查粒度粗**：关键词重叠是粗粒度启发式，无法替代人工语义判断。一个主题可能通过关键词检查但语义上并不准确。
4. **无人工标注**：没有人工标注的「正确答案」做对照，无法计算 precision/recall。
5. **单一模型**：仅测试 qwen3.7-plus，未对比其他模型。
6. **延迟受网络影响**：延迟数据来自单次运行，受网络波动影响。

## 与其他评测的关系

| 评测 | 性质 | 样本量 | 检查什么 |
|---|---|---|---|
| 黄金集评测 (`npm run eval`) | 本地确定性规则 | 200 例 | 规则引擎的合同通过率（不涉及模型） |
| 模型合同评测 (`npm run eval:model`) | 真实模型调用 | 12 例 | 模型输出的合同形状 + 零幻觉 + 接地 |
| 人工抽样复核 | 单人 40/200 | 40 例 | 规则引擎输出的主题/风险是否合理 |

三者互为补充：黄金集证明规则引擎的自洽性，模型合同评测证明真实链路的可靠性，
人工抽样复核是唯一的「人眼看过」证据。

## 复现方法

```bash
# 1. 启动 API 代理（需要 .env 中配置 BAILIAN_API_KEY）
npm run dev:api

# 2. 另一个终端运行评测
npm run eval:model
```

评测脚本位于 `scripts/evaluate-model.ts`，详细结果输出到 `artifacts/evaluation/model-contract-eval/results.json`（已 gitignore）。
