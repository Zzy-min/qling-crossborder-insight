# 200 例黄金集人工复核流程

当前 200 例均为 `machine-seeded`，用途是验证规则、证据绑定和评测管线的一致性；在完成双人复核前，不得对外称为“200 例人工黄金集”。

## 每例复核字段

- `id`：不可修改的样例编号。
- `family`：thermal / port-reset / combined / neutral。
- `body`：评论文本是否自然、是否存在歧义。
- `expected.themeIds`：标签是否由文本直接支持。
- `expected.riskIds`：政策风险是否与市场和产品相关。
- `reviewStatus`：两名复核者一致后才改为 `human-reviewed`。
- 复核记录：复核者代号、日期、分歧和最终依据，写入独立记录，不写真实姓名或联系方式。

## 流程

1. 两名复核者独立判断主题标签，不查看系统预测。
2. 标签一致时核对证据 ID、来源和日期。
3. 标签不一致时记录分歧，由第三次规则复核裁定。
4. 只有文本、标签、证据全部通过，才将状态改为 `human-reviewed`。
5. 每次状态变更后运行 `npm run eval`，保存报告摘要和 Git 提交号。

## 完成门槛

- 200/200 状态为 `human-reviewed`。
- 标签一致率、主题召回、风险召回、证据覆盖率均写入最终报告。
- 未知证据计数为 0。
- 对歧义样例有可追踪的处置记录。

## 当前进度

- 人工复核：0/200（双人流程，待第二人加入）。

## P1-2 单人抽样复核降级方案（2026-08-22）

### 背景
- 200 例黄金集全部为合成 fixture（4 模板 × 3 评论循环生成，每例 1 评论 1 产品）。
- 机器评估（`npm run eval`）：200/200 通过，0 失败——这是构造使然，不能说明真实模型表现。
- 双人独立复核流程（`reviewerA`/`reviewerB`/`resolution` 三包 + `auditHumanReview` 审计）已就绪，但单人参赛无法满足"两名独立复核者"硬门槛。

### 降级方案
- 从 200 例分层抽 40 例（4 family 各 10 例，固定种子 20260822，可复现）。
- AI 预填判断（`qling-qiqi-ai`）：逐字核对 body 文本是否支持 expected themeIds。
- 人类复核者扫视工作表确认（`artifacts/evaluation/single-review/sample-40.md`）。
- 双人流程保留为升级路径，待第二人加入即可直接复用。

### 复核结果（AI 预填，待人类确认）
- 40/40 accept，0 revise。
- 这符合预期：合成模板的标签是构造时硬编码的，body 文本必然支持 expected themes。
- 复核实质验证的是"模板标注内部一致"，不是"模型在真实数据上的表现"。

### 局限性（必须如实写入复赛材料）
1. 单人参赛，无双人独立复核。
2. 覆盖率 20%（40/200），未达 95% 门槛。
3. AI 预填判断，非纯人类独立判断。
4. 合成 fixture，40/40 accept 的信息量低，不构成模型质量证据。
5. 真正有说服力的模型质量证据是 P0-2 真实链路冒烟（commit 7d2ced5，9/9 检查通过，零幻觉引用），不是合成集复核。

### 升级路径
- 若复赛前有第二人加入：直接填 `reviewerB.json`，跑 `npm run review:audit`，可达双人门槛。
- 若时间有余：构造 5–10 例半真实数据集（基于真实跨境评论改写），用真实百炼链路跑，人工判断输出合理性——这比复核 200 合成例更有价值。
