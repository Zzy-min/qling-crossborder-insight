- 顶栏市场名称与按钮一致。参考图必须带评论编号，失败时保留文字概念。

## 问题

1. 定价情景只有一套数字。全部市场同时有美元、欧元、日元、英镑时，输入框仍沿用品类的美元默认价，币种标签却可能跟着第一组快照走。
2. 数据质量里的市场覆盖显示内部代码，和别处的中文市场名不一致。
3. 品类卡片、痛点标签用了另一套蓝色和表情符号，和现有工作台不在一个界面里。
4. 参考图原先只保存云端临时地址。2026-09-27 已改为代理立即下载并放在本机内存；刷新后仍指向本机，导出备忘录时嵌入图片。代理重启后图片失效，文字概念保留。

## 顺序

1. 定价按币种分开。美元沿用品类默认价；切到欧元、日元、英镑时，售价取该币种竞品中位数，到岸成本按售价的 45% 预填，并写明可以改。
2. 市场覆盖改成中文。
3. 品类卡片和痛点标签收回现有配色，去掉表情符号。
4. 参考图留存已做到本机代理内存和备忘录嵌入。不自动出图，不提交赛事。
5. 宽度低于 1180px 时，右侧决策栏隐藏，改由顶栏下方的紧凑条显示结论、分数和证据入口。宽屏仍使用侧栏。
6. 改良方案不再写未测量的温升、分贝、效率和成本区间。界面与备忘录标成设计假设，成本为未测算。
7. 非美元定价不再把 2,500 美元启动成本直接套进日元、欧元或英镑。换币后启动成本留空，填写后才计算保本销量。
8. 报告页与高管备忘录不再写“哈希校验通过”这类没有计算过程的说法。改为真实计算：对结构化痛点、合规事项、评分数值和质量统计做确定性序列化后取 SHA-256，界面、备忘录与证据 JSON 三处显示同一个指纹，并写明覆盖了几项聚类、几条引用、几条结论。同一份证据重复导出得到同一指纹；换市场范围、换模型模式或替换任意一条引用都会变。
9. `npm test` 此前会被 `artifacts/final/ppt-build/node_modules` 里的第三方测试文件打断（那是 PPT 构建留下的 junction）。vitest 排除规则改为同时覆盖嵌套 `node_modules` 与 `artifacts/`；同时修正 e2e 里仍按旧定价行为断言的两处用例。

## 定价报告一致性提升（2026-10-06，已完成）

### 调研与实施计划

1. 核对发现：市场机会页可以编辑售价、到岸成本和固定启动成本，但打印报告及 HTML 备忘录未接收这些参数；JSON 在成本缺失或情景无效时只导出 `null`，无法复核当时的输入。
2. 需求：页面、HTML/PDF 打印路径和 JSON 使用同一份当前币种假设，保留平台/广告费率与计算结果；缺失或无效的情景也保留输入，并明确标记状态。
3. 资源与数据流：`src/domain/market.ts` 构建 `PricingScenario`；`App.tsx` 持有当前输入，统一传给 `ReportView.tsx` 和 JSON 导出；`memo.ts` 与报告页复用字段格式及状态文案。状态为 `ready`、`missing-launch-cost`、`invalid`，只有 `ready` 附带计算结果。
4. 口径：[SBA 官方说明](https://www.sba.gov/counseling/plan-your-business/)给出保本销量为固定成本除以售价与单位变动成本之差。本项目单位变动成本包括到岸成本、平台和广告费率假设，保本件数向上取整。费率是当前演示假设，其他费用需另行核算。
5. 失败处理与隐私：无启动成本、非正贡献或无效参数时不导出保本结果；保持已有 JSON `pricingScenario` 的兼容形式，新增 `pricingAssumptions` 与 `pricingStatus`。证据指纹不包含定价参数，页面和备忘录明确标注该边界。验证使用仓库 CSV 样例，无需密钥或付费模型调用。

### 实施与验收

- 已完成：打印报告和 HTML 备忘录新增“定价假设与保本测算”，包含币种、三项金额、两项费率、单件边际贡献、贡献毛利率和保本销量。
- 用例：导入仓库样例 CSV，切换欧盟，填入售价 EUR 50、到岸成本 EUR 20、启动成本 EUR 3,000，三种导出路径一致呈现单件贡献 EUR 16.50、毛利率 33%、保本 182 件；无启动成本与亏损情景保留输入、不给保本结果。
