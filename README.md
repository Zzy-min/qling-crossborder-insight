# Qling 出海智察

面向中小跨境卖家的证据约束型 AI 市场决策工作台——把评论、竞品和政策数据变成可追溯到原始记录的进入决策，而不是 AI 摘要。AI 输出必须引用数据集中存在的记录 ID，编造引用会被合同层拒绝。

> CSDN AI+跨境黑客松参赛作品（场景：AI 市场洞察）｜团队：轻灵

## 核心特性

- **多品类出海场景**：内置「3C 氮化镓快充」、「智能宠物喂食器」、「户外便携储能」高潜出海类目，支持一键切换与自定义 CSV 导入。
- **全球市场合规雷达**：覆盖美（FCC/UL）、欧（RED/WEEE/EPR）、日（PSE/技适）、英（UKCA）四大跨境主力市场官方监管法规。
- **样本四象限与视觉概念改良**：展示方面提及率与预测负向占比；不足 20 条样本或 3 条证据不判断象限。概念方案仅为待验证的设计假设，不证明缺陷严重度或改良效果。
- **高管决策备忘录导出**：一键导出带数据链哈希与完整排版的独立 HTML/PDF《出海投资决策备忘录》及标准证据 JSON。
- **引用约束架构**：模型输出的 reviewId/policyId 必须存在于输入数据集中，未知引用拒绝并回退；引用合法不代表语义正确，仍须人工复核。
- **本地默认与来源身份**：在线分析/参考图生成须主动同意；演示商品/政策与用户 CSV 评论分开标记，购买标记不等于平台验证。
- **安全导出与双指纹**：HTML 动态文本转义，CSP 禁止脚本，PDF 使用浏览器打印。证据 JSON 1.2 包含 v2 原文/数据范围/分析版本指纹和独立定价情景指纹；它们是内容一致性检查，不是数字签名或真实性证明。旧指纹接口仍标为 v1。

## 演示工作流

1. **数据准备**：切换预置出海品类或导入评论 CSV，完成隐私、字段、重复记录与商品关联校验。
2. **市场机会**：查看机会指数、评分贡献、痛点四象限、竞品快照、定价敏感性与 AI 视觉改良方案。
3. **证据与风险**：从结论钻取原始记录，检查证据矩阵并查看确定性行动项。
4. **决策报告**：导出《出海投资决策备忘录》HTML/PDF，或导出证据 JSON（含批次/复核为 `1.3`，其他新报告为 `1.2`，历史格式保留）。

## 快速开始

**环境要求**：Node.js ≥ 20.6（需要 `--env-file-if-exists` 标志）

```powershell
npm install

# 终端 1：启动前端
npm run dev

# 终端 2（可选）：启动 AI 代理（需配置 .env）
npm run dev:api
```

前端默认运行在 `http://127.0.0.1:5173`，API 代理在 `http://127.0.0.1:8787`。
未配置 API Key 时前端自动回退到本地确定性分析，不报错。

## 评测口径说明

| 评测 | 命令 | 性质 | 样本量 |
|---|---|---|---|
| 黄金集评测 | `npm run eval` | 本地确定性规则（不涉及模型） | 200 例 |
| 模型合同评测 | `npm run eval:model` | 真实百炼调用（合同形状 + 引用有效性 + 主题接地；非准确率证明） | 12 例 |
| 人工抽样复核 | 见 `docs/evaluation/human-review.md` | 单人复核 | 40/200 |

三者互为补充：黄金集证明规则引擎自洽性，模型合同评测证明真实链路可靠性，人工抽样是唯一的人眼看过证据。详见 `docs/evaluation/model-contract-eval.md`。

## 项目结构

### 真实商品导入与本机工作区（首批技术实现）

在数据准备页选择商品 CSV 和评论 CSV，读取字段、映射 ASIN/SKU 等列、校验预览，并确认使用权限后导入。支持 UTF-8/BOM、逗号或制表符；最多 100 款商品 / 10,000 条评论，文件合计 20 MB。评分汇总、平台评论总数、购买标记、来源链接可以留空，保存为 `null`；商品市场、币种、售价和日期必须提供。重复冲突、孤立评论、跨市场冲突和个人信息列拒绝提交，正文疑似个人信息只作提示，不自动脱敏。模板中的记录仅为格式示例。

Dexie/IndexedDB 按独立工作区事务保存数据、映射和商品/市场/币种成本草稿；市场机会页选择“测算商品”，同币种的不同商品不共享成本，商品币种锁定。刷新后恢复，默认离线并按当前规则重建报告。真实商品不会使用演示成本或政策。到岸成本、平台/广告费率及固定投入留空时不当作零；明确填写零可保留。保存失败显示“未保存”，可下载工作区 JSON 备份；恢复备份创建新工作区，不覆写原记录。密钥不属于备份结构。演示切换不删除真实工作区。

工作区及 JSON 备份现为 v2；v1→v2 数据库升级使用事务，失败保留旧记录。旧范围成本在 `legacyDraft` 中原样保留，不自动分配到商品；新的逐商品成本需重新填写。新情景指纹 `/2` 包含商品标识、市场、币种，历史无商品上下文的接口仍为 `/1`。HTML、JSON 和打印报告均标识贡献测算对象，上方评论洞察仍覆盖选定市场的数据集合，不应混为单商品分析。

真实工作区完成本地/在线分析或在线失败后回退时，自动记录原文、原报告、版本和成本快照；也可在决策报告页手动保存当前报告。历史独立查看，不覆盖当前草稿，刷新不会重算旧记录。保存失败明确提示，可重试或单独下载分析存档。历史 HTML/PDF/JSON 标识原时间与存档指纹，指纹不证明来源或语义真实；历史图片不复用当前缓存。

数据库现为 v4（分析历史与复核独立存表），工作区快照仍为 /2；完整 JSON 备份使用 `qling-workspace-backup/4`，兼容旧 /3 与 v1/v2 工作区备份。恢复为新工作区及新历史 ID，失败事务回滚，不覆写原记录。整包上限 20 MB / 1,000 份历史 / 10,000 条复核，超限不截断，可分别下载存档；单份存档暂不支持独立导入界面。历史读取失败或未结束时不导出不完整整包。

真实工作区在线分析使用 `/api/analyze` 的 `protocolVersion: 2` 信封（含 `dataset`）：主题带固定方面标识、商品/市场范围，以及 `reviewId + field + quote + start/end` 的 UTF-16 原文锚点。服务端和客户端共用契约，检查片段、位置及作用域；只有 ID 的新版输出会被拒绝并明确回退，不保存无效在线结论。裸数据旧协议继续兼容，显示旧证据等级。正向、负向、中性和混合情绪分别保存；原文匹配并不证明情绪或主题正确，均待人工复核。

本地 `qling-rules/3` 按当前商品、市场和评论时间范围统计唯一评论；四象限使用 20% 提及率和 60% 负向占比的产品启发式，至少 20 条样本和 3 条方面证据才展示。混合/冲突情绪不直接计为负向；评分不再用重复提及数表示严重度。有限词规则不保证理解否定句，无匹配不表示没有痛点。锚点与统计随历史存档、JSON、HTML 和打印报告保存，旧报告不重算。真实语义评测仍待完成。

在“决策报告”保存当前报告并打开历史快照后，可逐原文锚点接受/驳回，接受时可以修正情绪，两种决定均需理由。复核事件独立追加保存，保留原预测及历次修订；仅已保存的最新接受决定参与人工确认统计，原分析评分不重算。原文与来源真实、产品危险性仍未独立验证，本机标注不是双人黄金集。保存失败不计入统计，可重试或下载未保存复核 JSON；该单独文件目前不提供导入 UI。

人工确认统计与修订理由随所选历史报告的 JSON/HTML/打印输出，并有独立复核指纹，原证据与情景指纹不变。完整工作区备份版本 `/4` 包含分析和复核记录，兼容旧 `/3` 与工作区快照；恢复创建新工作区，原分析内容保留，重新关联后的存档/复核指纹会改变，不是静默升级原报告。单份“下载分析存档”仍只含原分析，完整复核请导出报告或工作区备份。复核未读取或未保存时阻止该历史报告导出，存在未保存决定时阻止完整备份以免遗漏。

新版代理提示词 `qling-proxy-analysis/4` 要求模型逐评论引用各方面/情绪的原文片段，不只选代表评论；服务端对唯一、精确匹配的片段生成 UTF-16 坐标。不存在或歧义片段拒绝；模型显式给出的错误坐标不会被修正。客户端仍检查完整锚点。2026-10-06 新鲜真实复测中，/3 三类目契约通过，/4 四组场景、八个批次结构通过。51 条合成评论的引用由三个代表样例补齐到 51 条，但其中一条条件性混合体验仍被预测为负向；结构成功不等于语义准确率达标。详见实施记录及 `artifacts/evaluation/batches-real-1791285087378.json`。

真实工作区在线分析按商品/市场串行分批，每批最多 50 条，并受 JSON 24,000 字符 / 64,000 UTF-8 字节预算限制。全部资料先预检，正文超过 5,000 / 标题超过 1,000 字符或单条超预算时明确拒绝，不截断、不先发送部分输入。可取消并保留已完成批次；部分失败报告只采用成功范围，显示未完成评论 ID，原始完整输入保留在存档。预测统计与人工确认统计均只用成功范围作为分母，不推断平台总体。

网络/超时、限流和临时服务错误最多两次退避；引用契约、权限或参数错误不重试。批次状态、尝试次数、版本和范围随 JSON/HTML/打印保存并纳入指纹；数据变化防止旧结果覆盖。会话缓存以批次内容、提供商来源、模型及提示词版本隔离，复用前重新校验，不跨重启持久保存。取消无法撤回已发送的数据，也不保证提供商停止计费；服务器只会中止上游 fetch。

真实工作区市场机会页新增三情景成本明细，与旧版简化测算分开列示，不自动复制旧假设。基线/改良/压力分别填写售价、到岸或采购＋头程关税、佣金、履约、广告、仓储、退货增量净损失、改良成本及启动投入。所有参数默认未知；用户可明确不计入，或填写零。参数附币种、身份、来源和来源更新时间。切换到岸模式会按按钮说明清空另一组金额，避免重复扣减。未知变量不算贡献，未知启动投入或非正贡献不算保本销量；未列税费等须另外核对。

明细按工作区＋商品＋市场＋币种隔离保存，刷新和完整 JSON 备份恢复保留。使用兼容的工作区 /2 可选字段 `costSets`，每份为显式 `qling-cost-set/1`；旧工作区不补造假设，无须改变数据库索引。保存当前分析时冻结当时明细；历史报告不套用当前草稿，旧报告没有明细时不新增明细。包含明细的报告 JSON 版本 `1.4`，保留旧 evidenceDigest/scenarioDigest，同时在 `costComparison` 中提供三份独立明细指纹。HTML/PDF 使用相同输入、计算结果及指纹，来源文字转义，不生成可执行链接。

成本明细中可主动启用单变量敏感性分析：售价、广告费率、退货率和单件改良成本分别按 11 个等距条件点比较三种情景。默认范围为产品启发式，可调整，不是市场预测；一次只改变一个参数，其他成本保持原假设。缺项不补零，未知点不画成零线；非正贡献或未知启动投入不计算保本销量。曲线以颜色及不同线型区分，表格提供全部数值及未计算原因。

范围按显式 `qling-cost-sensitivity/1` 保存在明细成本快照，历史没有此字段时不自动生成图。包含范围的 JSON 导出为 `1.5`，新增独立 `costSensitivity.digest` 覆盖完整输入、范围、公式版本和条件结果，原指纹不变。打印展示曲线及条件表；HTML 只使用安全文本表格，不插入 SVG 或脚本。参数“实测”身份仅属于原成本，敏感性变化是条件假设，不更改原实测记录。

在保存并打开历史分析后，可以创建证据绑定的改良验证任务，记录设计假设、指标、方法及对照步骤、未知或用户假设新增成本。任务固定绑定原分析、原文锚点和该商品的历史成本指纹，不更新原预测。状态按待验证→验证中→已验证/已否定/暂缓追加，不能跳过验证中；终态只能追加同类结果，改变原假设须新建任务。已验证需要结果和采用决定，已否定需要结果且不采用。所有状态均为用户记录，未经独立核验，不是性能、认证或收益证明。

结果附件只在本机保存，不自动预览或执行；允许 TXT/MD/LOG、PNG/JPEG/WebP、PDF，单文件 5 MB、任务 20 个、工作区合计 10 MB，超限停止保存而不删除原内容。扩展名、文件头及 SHA-256 检查不是病毒扫描，尤其 PDF 仍需用户谨慎打开。结果和附件使用同一事务；失败显示未保存，可重试或下载含原快照、前序记录/相关附件及待保存内容的备份。单独未保存任务文件暂没有导入 UI。

包含任务的报告 JSON 为 `1.6`，HTML/打印列出采用与未采用方案、全部修订、结果、附件元数据及独立任务汇总指纹；附件原字节在完整工作区 `/5` 备份中。没有任务仍导出 `/4`，兼容旧备份。IndexedDB 版本 5 新增任务与附件表；恢复重新关联工作区/运行/任务/附件 ID，原文、假设及文件字节保持，重新关联指纹改变。任务读取或保存未完成时禁止历史报告导出，未保存任务禁止完整工作区备份，避免遗漏。

历史分析面板可主动选择两份已保存运行和明确商品核验可比性。比较使用归档原预测，不套用当前草稿或后续人工决定。商品/市场/币种、工作区、完整批次、原文样本及分析配置必须相同才计算方面输出差（百分点）；评论范围、日期/评分/语言/购买声明或模型/规则变化时只并列展示，不截取共同样本、不输出直接趋势差。唯一评论按方面去重，同方面冲突情绪归为混合，无提及不代表没有痛点。只检查明确商品，不因其他商品集合变化改变该范围。

同商品同币种的历史成本另行比较条件贡献与保本销量，缺明细或未知不补零，非正贡献不输出有限保本销量。比较 JSON/静态 HTML 使用独立 `qling-analysis-comparison/1` 和指纹，保留两次存档指纹、采样结构、引用锚点、历史成本输入/来源/结果；HTML 全部内容展开，打印不因折叠丢失原文或成本，禁止脚本/SVG/自动外链。超过 20 MB 明确拒绝、不截断。比较选择不持久化，刷新后须重新选择原存档；同一输入可重建相同比较指纹。当前导入缺少可验证的采样方案，不把不同评论集合视为可证明改良效果的纵向实验；独立试用/实验仍待完成。

导入页可将已通过校验的字段映射显式保存为本机模板。模板只含名称、表头、映射、保存时间及独立指纹，不含评论/商品正文、市场或币种的默认值、费用或密钥；名称和表头仍需用户自行检查隐私。新文件须先读取表头，再主动选择并应用模板；表头集合完全匹配时允许列顺序变化，缺列/改名/新增列拒绝复用。应用撤销旧预览及来源确认，必须重新校验与确认，不会自动导入。保存或恢复模板也不会应用映射。

IndexedDB 版本 6 新增独立映射模板表，最多 50 份，每文件最多 100 个表头、表头最长 200 字。只追加不覆盖；保存失败保留草稿供重试或下载，不冒充已保存，也不删除原库。模板使用 `qling-mapping-template/1` JSON 单独备份（不包含在工作区备份中），最多 100 KB；严格校验额外字段、必填映射、个人信息列及指纹，恢复创建新 ID 并保留来源指纹。刷新可重新选择已保存模板；旧异步读取不能覆盖新库状态，文件切换不会自动应用旧模板。

万条评论导入预览性能已在本机 Chrome 测量，分别使用约 0.46 MB 短评论与约 8.46 MB 混合长度合成评论。测量包括读取表头、自动化点击校验、Worker 解析和预览渲染，不包含 IndexedDB 提交或模型分析；记录 CPU/内存/系统/Node/浏览器、输入和相关源码 SHA-256 以及主线程 16 ms 心跳。目标为墙钟不超过 5 秒、心跳最大间隔不超过 200 ms（产品测试启发式，非行业标准）。详细数值以 `artifacts/product-improvement/import-performance-*/measurement.json` 为准；不泛化为所有设备或任意 20 MB 文件的承诺。

限制：当前不是完整卖家计划交付；真实图片下载兼容性和真实产品的合规适用性验证仍待完成。已保存图片的离线报告导出、人工合规台账已完成技术验证，不等于提供商实际图片、语义或法律准入验证。敏感性仅为单变量分析，不预测多因素联动或总收益。演示数据仍使用旧单请求预算，真实工作区使用上述批次预检。历史快照现可在两次明确许可后试验生图，生成/下载/本机保存/取消流程已经模拟验证，不代表真实闭环成功：本机 DNS 的保留地址解析仍被安全门禁拒绝。用户目前没有经授权真实评论，真实卖家试用和独立标注语义门禁保持未完成。浏览器数据可能被清理，本地保存不等同云备份，应定期导出 JSON。

### P1 界面收敛与人工合规复核

主路径仍为导入→分析→证据→报告，品牌与响应式决策栏保持原体系。工作区保存、在线许可和来源说明收敛到“工作区设置”；保存失败/回退仍主动显示。字段映射模板、兼容单评论入口、高级成本/敏感性、概念图、比较、语义复核与任务默认按需展开，没有移除原能力。分析形成结果后只自动存档一次，不再提供重复的“保存当前报告到历史”；保存失败仍可重试同一记录或下载分析存档。

人工合规复核只在已保存真实历史运行上编辑，独立于系统 `complianceRisks`；保留未知项、商品事实、适用条件、用户声明来源/日期、复核人及全局连续修订链，不改原评分与建议。`confirmed` 仅称“人工确认记录”，不代表官方认证、法律意见或准入通过；链接与指纹不证明来源真实性。来源 URL 仅文本展示，不自动访问。

IndexedDB v8 追加 `complianceReviews`，不改写旧表。含合规记录的完整工作区备份显式为 `/7`（可同时包含图片/任务/语义复核）；旧 `/3`–`/6` 仍可读且合规记录恢复为空，没有合规记录仍按原能力版本导出。恢复重新绑定运行/工作区/记录指纹，同一事务失败整包回滚，原记录不删除。失败记录支持独立 `qling-compliance-backup/1` 下载及函数校验，暂未提供独立合规备份导入 UI；完整工作区 `/7` 恢复入口已接通。

有合规记录的报告 JSON 为 `1.8`，图片/任务组合不会降级。页面、JSON、离线 HTML 和打印包含同一汇总及全部修订；合规读取/保存未完成或存在待处理失败记录时拒绝完整备份及历史报告输出，避免遗漏。详细逐文件说明、命令与证据见 `docs/superpowers/plans/p1-convergence-2026-10-07.md`。

生图服务端现支持 `/api/images` 协议 2：请求包含工作区/运行 ID、完整数据指纹、商品/市场/币种、稳定方面、精确原文锚点和未验证设计假设，不允许自由 `prompt`。服务端校验完整数据及 SHA-256、唯一锚点、原文/UTF-16 范围和商品作用域后构造提示词，只向提供商发送商品标题、引用片段、来源声明和假设，不发无关评论、成本或链接。来源声明、语义支持与实际效果都未因此被验证，概念图不是尺寸、性能、认证或量产证明。

协议 2 接受最多 100 款商品/10,000 评论、20 MB JSON 请求，最多 10 个锚点、单引用和假设各 1,000 字。返回绑定指纹和原绑定元数据，缓存隔离协议、数据、范围、运行、假设及模型。旧演示协议返回 `legacy-id-only` 等级，不冒充原文支持。历史快照的实验性生图必须同时确认全局在线处理与该快照发送；商品/评论/政策/来源及指纹发送给本机代理，不含成本，上游仅接收所选商品标题/方面/片段/来源/假设。不自动重试；取消或离开范围后不继续下载/保存。配额失败保留已校验内存图片，可单独备份或只重试本机保存；这类未保存图片不属于完整工作区备份，未完成时阻止该备份及报告导出。

客户端新增 `ProxyProvider.generateAnchoredConceptImage`：仅从完整指纹校验的分析存档构造新版请求，引用必须属于所选方面及同一商品/市场；离线聚合方面按所选原文关联商品，不按语言猜市场。响应必须精确匹配本次工作区、运行、数据、范围、方面、假设、锚点、来源及绑定指纹，即使错绑响应重新计算了自身哈希也拒绝。拒绝旧协议、额外 URL/密钥字段、危险图片类型或错误引用 ID；图片地址仅从代理路径和已校验 ID 构造。元数据最多 64 KB、严格 UTF-8/JSON；请求和读取支持取消，不自动重试。该生成方法只返回绑定元数据，须经下载与存储层核验图片字节；真实工作区 UI 尚未接线，结构匹配不证明图像语义或效果。

生图服务端在客户端断开时中止上游 fetch 和当前响应体读取，释放本机并发槽；取消的请求不发布图片、不写入缓存。正常完成或命中缓存不误判为取消。该机制不能撤回已经发送的内容，也不保证提供商停止生成或计费；仍需完成前端取消交互与真实提供商验证。

本机图片文件层已支持绑定下载、Blob 保存和单张离线备份：下载只使用已校验图片 ID 的代理路径，忽略返回对象的远端 URL；拒绝重定向、错误 MIME、超过 4 MB 的声明/流内容和伪装文件头。解码前检查 PNG/JPEG/WebP 尺寸头，最大边长 4,096、总像素 4,194,304，拒绝动画 PNG/WebP 与矛盾或截断头；仍须浏览器原生解码成功并核对尺寸。保存完整字节 SHA-256、记录指纹与原分析存档指纹，身份固定为“未验证概念参考”。这些门禁不是对浏览器解码器和元数据资源消耗的完全保证，也不是图像语义/效果验证。

IndexedDB v7 新增独立 Blob 表：追加不覆盖，单工作区最多 50 张/20 MB，全库图片字节最多 100 MB（元数据等另受浏览器存储额度约束）；额度不足不自动删除。保存失败抛错，取消或工作区失效会回滚；读取逐张解码校验，避免并行解码全部图片。`qling-concept-image-backup/1` 单张 JSON 包含原分析和图片字节，可离线核验恢复，未知版本/额外字段/坏编码/错指纹均拒绝；备份包含完整原评论与成本，应视为私有本机资料，不能未经确认外传。

原工作区导出/恢复按钮已接入图片：有图片时导出 `qling-workspace-backup/6`，没有图片继续明确使用 v4/v5，不静默改写历史格式。读取失败、坏图片或整包超过 20 MB 时拒绝整包，不悄悄遗漏图片。恢复在一个事务中追加工作区、分析、复核、任务、附件与图片，写入/额度/范围失效会整包回滚，原数据不删除。新本机图片记录显式为 `qling-concept-image-file/2`，保留原 v1 记录、原分析及原生图响应；新本机 ID 不伪装成新模型调用。重复恢复沿用同一原始来源，不形成递归来源链。在“决策报告→查看历史报告”可查看该运行的已校验本机图片、原文锚点与假设，并下载包含完整原分析/字节/来源的单张 JSON 备份。坏记录拒绝展示和下载，不自动删除或上传。管理面板不打印，另有已校验图片报告区进入打印/HTML 报告。生图为实验入口，不表示真实图片下载或语义质量已验证。

已保存历史图片现可进入离线报告：`qling-concept-image-report/1` 包含运行绑定、完整图片元数据和栅格 data URL，并有独立图片报告指纹；不改变历史证据或情景指纹。有图片时 JSON 报告显式使用 1.7，无图片保留原格式。HTML 内嵌图片，不请求远端图片；打印前重新读取校验并等待原生解码。保留原文锚点、未验证假设及恢复来源，不能把哈希当真实性证明。导出前再次校验本机字节，坏图、未保存图片、读取失败或整包超过 20 MiB 均拒绝输出，不静默遗漏。切换历史运行后旧异步请求不触发下载或打印；报告包含私有原文和成本，不代表公开分享授权。
